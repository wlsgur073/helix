## C3.1 — SECURITY.md claim-accuracy audit

**60 claims enumerated and verified; 56 ACCURATE as written.** The four exceptions and their
dispositions:

1. **OVERCLAIM (fixed in code):** "`~/.helix/audit.jsonl` is content-free" was violable on one
   path — the `'unavailable'` outcome's reason bypassed `persistedReason`'s reduction, so
   `checkCodexAvailable`'s catch (`src/verify/codex.ts`) could write a raw exception message
   (e.g. a spawn ENOENT path) into audit.jsonl; the code's own comment ("the 'error' outcome is
   the only unbounded free-text") was falsified by this second path, and the branch was untested.
   FIX: `persistedReason` now reduces the preflight-failure reason to the static label
   `codex preflight failed` (diagnostic detail stays in the live ToolResult, mirroring the
   'error' precedent); regression tests at the unit and handler/audit-row level; comment
   corrected.
2. **OVERCLAIM (fixed in docs):** "hard-blocks credential tokens (override-proof)" was true only
   for the NAMED provider-token tier; heuristic-detected and high-entropy secrets are per-leg
   policy-overridable (`dualVerify.egressPolicy`). The two auditors covering this sentence split
   (code-accurate vs reader-overclaim) — adjudicated as true-but-imprecise. FIX: SECURITY.md and
   README now state the tier split explicitly.
3. **OVERCLAIM (fixed in docs):** the residual-bounds bullet said a "per-target high-water
   counter" shipped; the shipped mechanism is the per-SCOPE witness (one MAC'd entry per ledger
   scope — as SECURITY.md's own witness section correctly says 24 lines later). FIX: wording
   aligned to "per-scope high-water witness".
4. **UNVERIFIABLE (accepted as written):** the launch-barrier paragraph's `/clear` observation
   describes Claude Code host behavior with no in-repo implementing code; it is honestly labeled
   as a live observation (2026-07-19) and is corroborated by the deploy runbook's independent
   record. No change.

Also verified in passing: no telemetry / no outbound path other than the opt-in dual-verify
spawn (dependency and source sweep); README and SECURITY.md are mutually consistent; the
