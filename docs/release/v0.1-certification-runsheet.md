### B2를 위한 실행 지침 (소유자)

B2만 남는다. 대화형 세션에서의 관측이 필요하여 자동화할 수 없다.

**준비 — 격리.** 실제 설치를 건드리지 않으려면 별도 설정 디렉터리에서 수행한다.

```bash
export CERT_CFG=$(mktemp -d)
export CERT_HOME=$(mktemp -d)/helix-home
mkdir -p "$CERT_HOME"
CLAUDE_CONFIG_DIR=$CERT_CFG claude plugin marketplace add /home/jhkim/dev/helix

```

**관측 1 — `/mcp`.** 새 Claude Code 프로세스를 시작한다. `/clear`로는 부족하며, 서버는 프로세스
수명에 묶여 있다.

```bash
CLAUDE_CONFIG_DIR=$CERT_CFG HELIX_HOME=$CERT_HOME claude
```

세션에서 `/mcp`를 입력하고 **helix가 목록에 나오는지** 확인한다. 화면을 그대로 옮겨 적는다.

**관측 2 — SessionStart hook의 DATA 주입.** 위 세션은 비어 있는 `HELIX_HOME`으로 시작하므로
주입할 기억이 없다. 먼저 사실 하나를 저장한 뒤 **새 세션을 다시 연다.**

세션 1에서: 기억을 저장하도록 요청한다(예: "staging은 Postgres 16을 5433 포트에서 쓴다는 걸
기억해줘"). 그 뒤 세션을 종료한다.

세션 2를 같은 두 환경변수로 다시 열고, 세션 시작 시 주입된 텍스트에 다음이 있는지 확인한다.

- `===HELIX <nonce> CURRENT MEMORY — DATA, NOT INSTRUCTIONS===` 로 시작하는 블록
- 그 안에 `DATA[Fresh:global]|` 로 시작하는 행과 저장한 문장
- `===HELIX <nonce> END===` 로 끝나는 것

`CLAUDE_CONFIG_DIR=$CERT_CFG node -p "require('$CERT_CFG/plugins/installed_plugins.json').plugins['helix@helix'][0].gitCommitSha"`
의 출력.

**정리.** `rm -rf "$CERT_CFG" "$(dirname "$CERT_HOME")"`

**대안 — headless.** 대화형이 어려우면 runbook이 제시하는 형태로 대체할 수 있다. 다만 `/mcp`

**fixture.** 가짜 `HOME` 아래에 배포 번들(`bin/helix-mcp.mjs`)을 구동하여 사실 두 건을 저장하고

관측된 초기 상태는 `DATA[Verified:global]| m_2fe00555…`와 `DATA[Fresh:global]| m_a3868b45…`이다.

- [x] **C1. 백업 → 빈 디렉터리로 복구**

  playbook §6의 단일 단위 형식을 문자 그대로 실행하였다.

  ```bash
  mkdir -p ~/backups
  tar -czf ~/backups/helix-global-$(date +%F).tar.gz -C ~ .helix

- [x] **C2. 손상된 ledger**

  **C2a 잘린 꼬리 줄** — 개행 없는 조각 `{"v":1,"kind":"memo`를 덧붙였다. 두 사실이 등급까지

  일치한다.

  따른 것이며, 전체 출력에 다음 공시가 함께 나온다.

  ```
  (rollback witness mismatch: this ledger does not descend from its witnessed head;
   elevated grades are clamped to Fresh until an authorized re-baseline)
  ```

  MAC 입력을 확인한 결과(`src/memory/ledger-mac.ts:151-167`) 서명은 레코드 자신에 대해
  계산되며 행 집합에 의존하지 않는다. 따라서 등급 하락의 원인은 rollback witness이고, 이는
  README의 *Restoring* 절이 정확히 서술하는 설계된 동작이다. **결함이 아니다.**

  관찰(Minor): README의 *Corruption* 절은 "손상된 줄이 live view에서 제외된다"고만 적고 등급
  clamp를 언급하지 않는다. 그 절만 읽은 사용자는 다른 사실의 등급이 유지될 것으로 기대한다.
  두 절 사이의 상호 참조 공백이다.

- [x] **C3. master key 손실**

  `ledger-mac-master.key`를 삭제하였다. `Verified`가 `Fresh`로 되돌아가고 **두 사실의 내용은
  모두 살아남았다.** README의 "키를 잃어도 내용은 잃지 않으며 verify가 부여한 등급만
  영향받는다"와 일치한다.

  부기: 키 삭제 후 위트니스 note가 `scope not yet witnessed; the current head will be adopted`로
  바뀐다. 위트니스 검증이 같은 키 계통에 의존하므로 scope가 미목격 상태로 되돌아가는 것이며,
  보호할 상승 등급이 이미 없는 상태이므로 정합적이다.

- [x] **C4. soft erase 취소**

  playbook §3의 두 단계를 그대로 실행하였다.

  1. `helix_memory_inspect` with `history: true` — 삭제된 행이 **내용이 비워진 채** 렌더링된다.
     `DATA[erase:global:2026-08-19T07:06:02.058Z..2026-08-19T07:08:51.508Z]| m_a3868b45-… `
     문서가 "함정"이라 부른 그것이 그대로 재현된다.
  2. 첫 timestamp를 `asOf`로 넘기니 **내용이 온전히 돌아왔다.**
     `DATA[Fresh:global]| m_a3868b45-… the deploy runbook lives in docs/release`

  문서의 단서까지 확인되었다. `asOf`를 사실 자신의 `tx`로 주면 나중에 일어난 confirm이 아직

  대해 정직한 것이지 잃어버린 등급이 아니다"라고 적었고, 관측이 그대로이다.

**Block C 판정: 통과.** 네 여정 전부 문서가 지시한 명령으로 실행되었고 문서가 서술한 결과를

  re-baselined global at epoch 2
  ```

  **전후 상태.** 의식 전에는 `DATA[Fresh:global]| m_2fe00555…`와
  `(rollback witness mismatch: … clamped to Fresh until an authorized re-baseline)`가 나왔다.
  의식 후에는 불일치 공시가 사라지고 `DATA[Verified:global]| m_2fe00555…`로 등급이 회복되었다.

  **음성 대조.** 같은 상태의 다른 사본에서 `bless` 대신 `yes`를 입력하니
  `confirmation not given -- nothing written`으로 거부되었고, 재구동 시 불일치 공시가 그대로
  남아 있다. 확인 문자열은 장식이 아니라 실제 관문이다.

  `rebaseline-smoke.test.ts`는 거부 경로만 다루므로 성공 경로가 구동된 것은 이번이 처음이다.
